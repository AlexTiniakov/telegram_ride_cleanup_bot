# Telegram Ride Cleanup Bot

Бот підтримує порядок у групі пошуку попутників: перевіряє оголошення й видаляє їх після завершення вказаного часу.

## Обов'язкові поля

Для звичайних учасників потрібні хештег, календарна дата та час.

- Хештеги: `#Водій`, `#Пасажир`, `#Водитель`, `#Пассажир`. Регістр неважливий.
- Дата: день і місяць; рік необов'язковий. Приклади: `06.10`, `6.10.`, `06,10`, `06,10,`, `06.10,2026`, `06,10.26`, `06/10/2026`, `06-10-26`, `6 жовтня`.
- Час: `07:30`, `7:30`, `07.30`, `7-30`, `7 год 30 хв` або діапазон.

Дата й час можуть стояти на різних рядках. Пробіли біля роздільників, кома замість крапки й крапка після дати підтримуються. Неможливі календарні дати на кшталт `31.02` не виправляються автоматично. Довільні помилки не гарантують розпізнавання; найнадійніший формат — `06.10.2026 07:30`.

## Дозволені дати

- Поїздки на сьогодні можна публікувати будь-коли.
- Поїздки на завтра — лише з 15:00 поточного дня (за Києвом). Опубліковане раніше видаляється.
- Поїздки на післязавтра й пізніше видаляються.

Враховується час надсилання повідомлення, а не редагування: якщо оголошення на завтра надіслане о 10:00 і відредаговане о 16:00, воно однаково видаляється.

Без хештега, розпізнаної дати або часу повідомлення видаляється мовчки. Лише `сьогодні` або `завтра` без календарної дати недостатньо. Колишнє правило перенесення часу без дати на завтра більше не застосовується.

## Час видалення

Усі розрахунки виконуються в часовому поясі `Europe/Kyiv`.

- `06.10 07:30` — видалення 6 жовтня о 07:35.
- `06.10.\n7:30 - 8:00` — 6 жовтня о 08:05.
- `06.10 21:00 ...21:30` або `21:00…21:30` — о 21:35.
- `06.10 16:30-40` — о 16:45.
- `06.10 16:50-10` — о 17:15.
- `06.10 23:30-00:15` — 7 жовтня о 00:20.

Затримка становить 5 хвилин після часу або кінця діапазону. Черга перевіряється приблизно раз на 2 секунди; мережа й навантаження можуть затримати видалення. Якщо строк уже минув, повідомлення потрапляє під найближчу перевірку. Явна дата не переноситься на завтра.

Без року використовується рік надсилання. Якщо отримана дата більш ніж на 180 днів раніше дня надсилання, використовується наступний рік. Для двозначного року додається 2000: `26` означає 2026. Для далеких поїздок указуйте повний рік.

## Винятки

Власник та адміністратори групи звільнені від усіх цих перевірок. Статус автора перевіряється при надходженні повідомлення й повторно перед запланованим видаленням. Якщо перевірка прав недоступна, бот не видаляє повідомлення.

Інші боти (наприклад, `@inbox_77bot`) не звільняються, навіть якщо вони адміністратори групи: їхні повідомлення перевіряються як повідомлення звичайних учасників. Щоб бот узагалі отримував повідомлення інших ботів, у [@BotFather](https://t.me/BotFather) потрібно ввімкнути **Bot-to-Bot Communication Mode** і вимкнути **Group Privacy**; бот має бути адміністратором групи. Без цього Telegram не надсилає йому повідомлення інших ботів.

Повідомлення від імені групи/каналу також пропускаються: особу автора перевірити неможливо. Службові події Telegram та особисті чати не модеруються.

Правила поширюються на текст і підписи до медіа. Звичайні повідомлення, стікери або медіа без потрібного підпису від звичайних учасників видаляються.

## Редагування та збереження

Бот перевіряє нові й відредаговані повідомлення. Після редагування коректного оголошення розклад оновлюється; якщо обов'язкове поле видалене, повідомлення видаляється. Пояснення не надсилаються ані в групу, ані в особисті.

Черга зберігається у `rides.sqlite3` та переживає перезапуски. Наявні завдання під час оновлення правил не скасовуються й не перераховуються. Старі завдання без ID автора виконуються без перевірки його прав. Бот не сканує всю історію групи.

Бот перевіряє формат, а не достовірність маршруту, ціни, телефону чи кількості місць. Для одного повідомлення створюється одне завдання; рекомендується публікувати одну поїздку на повідомлення.

## Запуск

Потрібні Python 3.11+ та права адміністратора на видалення повідомлень у групі.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
# Перед запуском установіть BOT_TOKEN у середовищі.
python bot.py
```

На сервері процес запускається через `telegram-ride-bot.service`.

```bash
sudo systemctl status telegram-ride-bot --no-pager
sudo journalctl -u telegram-ride-bot -n 50 --no-pager
```

Перевірки:

```bash
python test_parser.py
python test_admin.py
python test_tags_dates.py
python test_moderation.py
python test_rules_window_bots.py
```
